# Adding a parameter at the Rust level

This guide walks through adding one new scalar parameter to an existing bridged parameter type (a `*_PRM` type such as `STEBBS_PRM`), from the Fortran kernel through the Rust bridge to the YAML and the Python data model.
It lists the places where a mistake fails loudly, the places where it fails silently, and ends with a checklist.

Line numbers are for the commit that added this guide; follow the symbol names if they have moved.
Worked examples in the history: commit `4573f9f898` (one STEBBS scalar, `InternalMassArea`) and commit `6aae28c5c7` (six STEBBS shading and heating fields).

## How a value travels

```text
YAML -> (supy: Pydantic, model_dump(exclude_none=True)) -> yaml_config.rs
     -> Rust struct (starts from the Fortran default) -> to_flat() -> f64 buffer
     -> c_api/<type>.f95 *_unpack -> kernel TYPE in src/suews/src/suews_type_*.f95
```

The default of every field is decided in Fortran.
`<prefix>_default_from_fortran` (generated by `impl_state_module_fns!`, `src/suews_bridge/src/codec.rs:213`) asks the C-API facade to pack a freshly initialised *shadow* type, and the YAML reader then overwrites only the keys it finds.
The shadow initialisers are almost all `0.0`, so **a key that is absent from the YAML reaches the kernel as zero, without a message**.
On the supy path a Pydantic field whose value is `None` is dropped before Rust sees it (`src/supy/_run_rust.py:943`), so it counts as absent too.
Choose what absence should mean for your parameter before you start (step 1 and step 6).

Everything below is hand-written.
The only generated file in the bridge is `output_cols.rs` (output columns, from `build.rs`).

## The eight steps

### 1. Kernel type (Fortran)

Add the component to the `TYPE` in `src/suews/src/suews_type_*.f95` (for STEBBS: `TYPE, PUBLIC :: STEBBS_PRM` at `src/suews/src/suews_type_stebbs.f95:86`), with its units in a comment, and use it in the physics.
The initialiser you write here is the value the kernel uses when nothing else sets it, so choose it deliberately rather than leaving `0.0D0` by habit.

### 2. C-API facade (Fortran)

In `src/suews_bridge/c_api/<type>.f95` (annotated reference: `c_api/stebbs_prm.f95`):

- add the component to the shadow type (`type :: stebbs_prm_shadow`, line 40). The shadow initialiser is what Rust receives as the default; make it equal the kernel initialiser from step 1;
- raise `SUEWS_CAPI_<TYPE>_LEN` (line 37) by the number of values you add, and raise `SUEWS_CAPI_<TYPE>_SCHEMA_VERSION`;
- add one line to `*_pack` (shadow -> flat, line 138) and one to `*_unpack` (flat -> kernel type, line 221), **at the same position in both**;
- an INTEGER component is a `real(c_double)` in the shadow and comes back into the kernel type with `nint(flat(idx))` (line 255). A LOGICAL is packed as 1 or 0 with `merge(1.0_c_double, 0.0_c_double, ...)` (line 213) and comes back with `flat(idx) >= 0.5_c_double` (line 295).

`*_unpack` is what the driver calls on every run (`c_api/driver.f95`, e.g. `call stebbs_prm_unpack(...)`), so its order, not only pack's, decides which kernel variable receives each number.

### 3. Rust module

In `src/suews_bridge/src/<type>.rs` (reference: `stebbs_prm.rs`):

- raise `<TYPE>_FLAT_LEN` (line 33) and `<TYPE>_SCHEMA_VERSION` to the values from step 2;
- add the struct field and its entry in `impl Default` (line 94). The `Default` value must equal the shadow initialiser;
- add the field to `from_flat` (line 152), `to_flat` (line 297) and `<prefix>_field_names()` (line 378), at the same index as in pack and unpack;
- if the value has a valid set (a switch, a fraction), check it in `from_flat` and return `BridgeError::BadState` otherwise (pattern: `internal_shading`, `destination_waste_heat`).

The `impl_state_module_fns!` invocation at the bottom of the file (line 441) does not change.

### 4. Nested types (only if your type is embedded in another)

Some types are embedded whole in others: `OhmPrm`, `SoilPrm`, `BioCo2Prm`, `LaiPrm` and `WaterDistPrm` sit inside every `lc_*_prm` type.
The parent facades copy the nested components field by field in their own pack and unpack (`c_api/lc_evetr_prm.f95:162` and `:241` for `ohm`), and the parent Rust `from_flat` slices the buffer with hard-coded bounds (`lc_evetr_prm.rs:96`, `OhmPrm::from_flat(&flat[6..23])`; the module docs carry the full offset table).
Adding a field to a nested type therefore means, in **every** parent: raise the parent's LEN and `*_FLAT_LEN`, shift every later slice bound, and add the field to the parent facade's inlined pack and unpack.

### 5. Names

The YAML (Pydantic) name and the Rust field name are linked through `src/suews_bridge/src/field_renames.rs`.
If the Pydantic name does not reduce to the Rust name, add the pair to `FIELD_RENAMES` (line 42) and to its mirror `ALL_FIELD_RENAMES` in `src/supy/data_model/core/field_renames.py`, then update the count in the Rust test (`assert_eq!(FIELD_RENAMES.len(), ...)`, line 2228).
`scripts/lint/check_rust_yaml_aliases.py` checks that the two lists agree.

### 6. YAML reader

`src/suews_bridge/src/yaml_config.rs` has two reading styles (see its module docs):

- STEBBS and building archetype: map-based. `apply_stebbs_overrides` (line 1842) passes each YAML key through `normalise_field_name` (line 212) and `set_mapped_value` (line 332). No code is needed for a new field, but a YAML key that matches no Rust field name after normalisation is dropped without a message.
- Every other type: explicit paths. Add a `read_numeric(root, &[...])` line in the relevant `apply_*_overrides` (for example `apply_soil_overrides`, line 494). Write down in a comment what happens when the key is absent; at present absence means the shadow default.

Site-level scalars passed outside the member types (`lat`, `z`, `z0m_in`, ...) are a separate fixed buffer: `SiteScalars` in `src/suews_bridge/src/sim.rs`, read by `apply_site_scalar_overrides` (line 2234), encoded by `encode_site_scalars` (`sim.rs:485`) and unpacked by `unpack_site_scalars` (`c_api/driver.f95:1142`), with the length pair `SUEWS_CAPI_SITE_SCALARS_LEN` (`sim.rs:126` and `driver.f95:64`).

### 7. Python data model

Add the Pydantic `Field` with a non-`None` default or a validator, and any entry in the required-field tables (`src/supy/data_model/validation/required_fields.py`) if the value has no safe default.
If the YAML schema changes, raise `CURRENT_SCHEMA_VERSION` (`src/supy/data_model/configuration/version.py:26`) and add a migration in `src/supy/util/converter/yaml_upgrade.py`; `scripts/lint/check_schema_version_bump.py` enforces this (see `.claude/rules/python/schema-versioning.md`).

### 8. Tests

- Each module's `schema_matches_expected_dimensions` and `default_state_roundtrip` tests (`stebbs_prm.rs:521` and `:527`) catch a LEN mismatch and a Rust `Default` that differs from the shadow.
- Nothing in the Rust tests exercises `*_unpack` (Rust never calls it), so a swapped unpack line is invisible to them. Add a wiring test that sets each new field to a distinct value and checks the effect on the kernel (model: `test/physics/test_stebbs_parameter_wiring.py`).
- Run `cargo test --features physics` in `src/suews_bridge` (after `make -C src/suews all`) and `make test-smoke`.

Not needed for a new field in an existing type: `build.rs`, `ffi.rs`, `lib.rs`, the `impl_state_module_fns!` invocation, the driver's site-member table of contents.
A brand-new type needs all of those plus a new member index on both sides (`SUEWS_CAPI_SITE_MEMBER_*` in `driver.f95`, `SITE_MEMBER_*` in `sim.rs`, which is 0-based).

## What fails loudly and what fails silently

Loud (a test or a run-time `BadState` / `BadBuffer`):

- Fortran `SUEWS_CAPI_<TYPE>_LEN` versus Rust `<TYPE>_FLAT_LEN` (`<prefix>_default_from_fortran`, `validate_flat_len`);
- Fortran versus Rust schema version (`<prefix>_schema_info`, `from_values_payload`);
- Rust `Default` versus shadow initialisers (`default_state_roundtrip`);
- the `FIELD_RENAMES` count; the Python schema version.

Silent (the run goes ahead with a wrong value):

- `*_unpack` order differing from `*_pack` and Rust: the right number lands in the wrong kernel variable;
- `<prefix>_field_names()` shorter than `to_flat()`: `to_map` zips the two and drops the tail (only `<prefix>_schema_info` compares the lengths);
- Fortran accepting a buffer longer than LEN (the facades check `n_flat < LEN` only);
- a STEBBS or archetype YAML key that matches no Rust field (`set_mapped_value` drops it);
- an absent key, or a Pydantic `None`, leaving the shadow default (usually zero);
- a hard-coded slice bound in a parent type that starts in the wrong place while the total length is right;
- the two `SUEWS_CAPI_SITE_SCALARS_LEN` constants and the index of each site scalar, which are not compared at run time.

## Checklist

- [ ] Kernel `TYPE` component added, with units and a deliberate initialiser.
- [ ] Shadow component added; its initialiser equals the kernel's.
- [ ] Facade LEN and schema version raised.
- [ ] One line in `*_pack` and one in `*_unpack`, at the same position; INTEGER via `nint`, LOGICAL via `>= 0.5`.
- [ ] Rust `*_FLAT_LEN` and `*_SCHEMA_VERSION` match the facade.
- [ ] Struct field, `Default` (equal to the shadow), `from_flat`, `to_flat` and `*_field_names()` all at the same index.
- [ ] Range check in `from_flat` if the value has a valid set.
- [ ] Nested type: every parent's LEN, slice bounds and inlined pack/unpack updated.
- [ ] `FIELD_RENAMES` (Rust and Python) and its count test updated if the names differ.
- [ ] YAML reader: explicit `read_numeric` path added, or the map-based name confirmed to match; absence handled on purpose.
- [ ] Pydantic field with a non-`None` default or a validator; required-field entry if needed; schema version and migration if the schema changed.
- [ ] Wiring test with distinct values; `cargo test --features physics` and `make test-smoke` pass.
