# Adding a parameter at the Rust level

This guide walks through adding one new scalar parameter to an existing bridged parameter type (a `*_PRM` type such as `STEBBS_PRM`), from the Fortran kernel through the Rust bridge to the YAML and the Python data model.
It lists the places where a mistake fails loudly, the places where it fails silently, and ends with a checklist.

Read the [design](RUST_BRIDGE_DESIGN.md) and the canonical
[bridge contract](../.claude/rules/rust/bridge-contract.md) first. This recipe
distinguishes the legacy construction path from the requirements for new fields.

Line numbers were verified at commit `f0a807ada2`; follow the symbol names if they have moved.
Worked examples in the history: commit `4573f9f898` (one STEBBS scalar, `InternalMassArea`) and commit `6aae28c5c7` (six STEBBS shading and heating fields).

## How a value travels

```text
YAML -> (supy: Pydantic, model_dump(exclude_none=True)) -> yaml_config.rs
     -> Rust struct (starts from the Fortran default) -> to_flat() -> f64 buffer
     -> c_api/<type>.f95 *_unpack -> kernel TYPE in src/suews/src/suews_type_*.f95
```

In this legacy construction path, missing fields can retain Fortran shadow
initialisers; the YAML reader also contains Rust-side fallbacks.
`<prefix>_default_from_fortran` (generated by `impl_state_module_fns!`, `src/suews_bridge/src/codec.rs:218`) asks the C-API facade to pack a freshly initialised *shadow* type, and the YAML reader then overwrites only the keys it finds.
The shadow initialisers are almost all `0.0`, so **a key absent from the YAML can reach the kernel as zero, without a message**.
On the supy path a Pydantic field whose value is `None` is dropped before Rust sees it (`src/supy/_run_rust.py:948`), so it counts as absent too.
That is the legacy behaviour, and it is being removed.

## The rule: the bridge passes values through

The required contract is that the Rust bridge (`src/suews_bridge/` and the
C-API shadow types it starts from) must not supply missing model values.

1. If a value the kernel uses is missing upstream, the bridge fails and names the missing parameter by its YAML path (and, for a list, the index or the length it needs).
2. Defaults live in one place only: the supy data model (the Pydantic models under `src/supy/data_model/`), documented and visible. Never in the bridge.
3. A field needed only under particular options may be carried as explicitly absent when those options are off (for example `Option<T>` in Rust, or NaN in a flat buffer the kernel does not read), but never given a substituted number.
4. The Rust CLI (`suews-engine`) goes through the same bridge and follows the same rule; `SiteScalars::default()` and other Rust-side defaults are not exempt.

An implicit zero through a derived `Default`, `unwrap_or_default`, `unwrap_or(0.0)`, a zero-initialised shadow type, or "keep the default when the key is absent" is not acceptable in new code.
Much of the existing reader still keeps defaults for absent keys; that is being converted, and a new parameter must not add to it.

The mappings below are hand-written. `build.rs` generates `output_cols.rs` for
output widths; it does not generate parameter pack/unpack mappings.

## Refreshing the bridge test inputs

After a schema or data-model change, regenerate the resolved engine YAML fixtures
with the project venv active, from the repository root:

```bash
python scripts/suews/gen_bridge_fixtures.py
```

The generator uses `SUEWSConfig.from_dict` (as in the sample-output check) and the shared
`config_to_engine_yaml` hand-off used by `suews run`.
Commit the generated files in `test/fixtures/bridge/` separately from code changes.
`make test` checks them byte for byte against an in-memory regeneration and names
this command if either fixture is stale.
Rust tests start from these resolved fixtures and change only the construct under test (a legacy spelling, a family form, a removed or malformed key), so a required read added later does not fail them on an unrelated key.

## The eight steps

### 1. Kernel type (Fortran)

Add the component to the `TYPE` in `src/suews/src/suews_type_*.f95` (for STEBBS: `TYPE, PUBLIC :: STEBBS_PRM` at `src/suews/src/suews_type_stebbs.f95:86`), with its units in a comment, and use it in the physics.
Document any representation initialiser and the established valid range. The
application default, if any, belongs to the Python data model in step 7; the
bridge must require the resolved active value before the kernel can consume it.

### 2. C-API facade (Fortran)

In `src/suews_bridge/c_api/<type>.f95` (annotated reference: `c_api/stebbs_prm.f95`):

- add the component to the shadow type (`type :: stebbs_prm_shadow`, line 40). Keep representation initialisation consistent with the kernel type, but do not let that initialiser stand in for missing input;
- raise `SUEWS_CAPI_<TYPE>_LEN` (line 37) by the number of values you add, and raise `SUEWS_CAPI_<TYPE>_SCHEMA_VERSION`;
- add one line to `*_pack` (shadow -> flat, line 138) and one to `*_unpack` (flat -> kernel type, line 221), **at the same position in both**;
- an INTEGER component is a `real(c_double)` in the shadow and comes back into the kernel type with `nint(flat(idx))` (line 255). A LOGICAL is packed as 1 or 0 with `merge(1.0_c_double, 0.0_c_double, ...)` (line 213) and comes back with `flat(idx) >= 0.5_c_double` (line 295).

`*_unpack` is what the driver calls on every run (`c_api/driver.f95`, e.g. `call stebbs_prm_unpack(...)`), so its order, not only pack's, decides which kernel variable receives each number.

### 3. Rust module

In `src/suews_bridge/src/<type>.rs` (reference: `stebbs_prm.rs`):

- raise `<TYPE>_FLAT_LEN` (line 33) and `<TYPE>_SCHEMA_VERSION` to the values from step 2;
- add the struct field and, where required by the existing representation, its entry in `impl Default` (line 94). Keep it consistent with the shadow initialiser; neither is an application default or a substitute for required input;
- add the field to `from_flat` (line 152), `to_flat` (line 297) and `<prefix>_field_names()` (line 378), at the same index as in pack and unpack;
- if the value has a valid set (a switch, a fraction), check it in `from_flat` and return `BridgeError::BadState` otherwise (pattern: `internal_shading`, `destination_waste_heat`).

The `impl_state_module_fns!` invocation at the bottom of the file (line 441) does not change.

### 4. Nested types (only if your type is embedded in another)

Nested types have different parent sets:

| Nested type | Parent Rust types |
|---|---|
| `OhmPrm` | `LcPavedPrm`, `LcBldgPrm`, `LcEvetrPrm`, `LcDectrPrm`, `LcGrassPrm`, `LcBsoilPrm`, `LcWaterPrm` |
| `SoilPrm` | `LcPavedPrm`, `LcBldgPrm`, `LcEvetrPrm`, `LcDectrPrm`, `LcGrassPrm`, `LcBsoilPrm`, `LcWaterPrm` |
| `BioCo2Prm` | `LcEvetrPrm`, `LcDectrPrm`, `LcGrassPrm` |
| `LaiPrm` | `LcEvetrPrm`, `LcDectrPrm`, `LcGrassPrm` |
| `WaterDistPrm` | `LcPavedPrm`, `LcBldgPrm`, `LcEvetrPrm`, `LcDectrPrm`, `LcGrassPrm`, `LcBsoilPrm` |

Before changing lengths, schema versions or offsets, enumerate the actual parent struct fields and their facade pack/unpack sites.
`OhmPrm` and `SoilPrm` are common to all seven land-cover parents; biogenic CO2 and LAI are vegetation-only, and water distribution is absent from `LcWaterPrm`.
The parent facades copy the nested components field by field in their own pack and unpack (`c_api/lc_evetr_prm.f95:162` and `:241` for `ohm`), and the parent Rust `from_flat` slices the buffer with hard-coded bounds (`lc_evetr_prm.rs:96`, `OhmPrm::from_flat(&flat[6..23])`; the module docs carry the full offset table).
Adding a field to a nested type therefore means, in **each actual** parent: raise the parent's LEN, `*_FLAT_LEN` and schema versions, shift every later slice bound, and add the field to the parent facade's inlined pack and unpack.

### 5. Names

The YAML (Pydantic) name and the Rust field name are linked through `src/suews_bridge/src/field_renames.rs`.
If the Pydantic name does not reduce to the Rust name, add the pair to `FIELD_RENAMES` (line 42) and to its mirror `ALL_FIELD_RENAMES` in `src/supy/data_model/core/field_renames.py`, then update the count in the Rust test (`assert_eq!(FIELD_RENAMES.len(), ...)`, line 2229).
`scripts/lint/check_rust_yaml_aliases.py` checks that the two lists agree.

### 6. YAML reader

**Never add new calls to the legacy optional readers** (`read_numeric`, `read_i32`, `read_string`, `read_numeric_sequence`, `read_sized_numeric_sequence`, `read_finite_numeric`, or `read_sequence`) in `src/suews_bridge/src/yaml_config.rs` (BR-02).
CI enforces a downward-only ratchet in `scripts/lint/check_rust_optional_reads.py` against `scripts/lint/rust_optional_reads_baseline.json` (#2079): per-function counts of the five legacy optional readers (`read_numeric`, `read_i32`, `read_string`, `read_numeric_sequence`, `read_sized_numeric_sequence`) cannot increase.
When converting an existing legacy read site to a strict helper (#2002), lower the baseline in the same pull request with:

```bash
python scripts/lint/check_rust_optional_reads.py --write-baseline
```

`src/suews_bridge/src/yaml_config.rs` has two reading styles (see its module docs):

- Every non-map type: explicit paths in the relevant `apply_*_overrides` function (for example `apply_soil_overrides`, line 854). Use the strict `require_*` helpers in `src/suews_bridge/src/yaml_config.rs`:
  - `require_numeric(root, path, at)` (line 398) for a finite `f64`;
  - `require_i32(root, path, at)` (line 422) for an exact `i32` (no rounding tolerance);
  - `require_string(root, path, at)` (line 436) for a string;
  - `require_sized_numeric_sequence(root, paths, at, required)` (line 459) for a numeric list of at least `required` finite entries (accepting candidate path aliases in order);
  - `require_sequence(root, path, at, required)` (line 496) for a list of at least `required` YAML mappings (such as `vertical_layers.roofs`).
  Each wraps `require_value` (line 382), unwraps the `RefValue` wrapper (`{value: x}`) once, and returns `Err(String)` naming the missing, `null`, malformed or non-finite key via `yaml_path_display` (line 358) using the site prefix from `site_yaml_at` (line 307).
  Note that `yaml_path_display` consults `FIELD_RENAMES` only (not `FIELD_COMPAT_ALIASES`), so any strict read of a STEBBS or building-archetype field whose current name lives in `FIELD_COMPAT_ALIASES` must name that key explicitly in its error message (lines 350-356).
- STEBBS and building archetype: map-based. `apply_stebbs_overrides` (line 2526) and `apply_building_archetype_overrides` (line 2461) pass each YAML key through `normalise_field_name` (line 558) and `set_mapped_value` (line 678). A matching name can be picked up without a new assignment, **but map-based loading alone does not satisfy BR-02**: an absent or `null` key keeps the shadow default, and an unmatched key is currently dropped without a message. For any new field consumed under active options, enforce its presence explicitly (for example with `require_numeric` / `require_i32` when the option is active) rather than relying on the shadow initialiser.

Choose between an unconditionally required read (BR-02) and a conditional or option-gated read (BR-02/BR-03) according to whether the kernel always consumes the parameter or reads it only under specific physics switches or active land-cover surfaces:

```rust
// Unconditionally required parameter (consumed every timestep, BR-02):
// `properties.land_cover.water.flowchange` is reported every timestep even when
// `water.sfr == 0` (see `apply_site_scalar_overrides`, lines 3061-3080).
// `yaml_path_display` preserves the public path
// `sites[gridiv=...].properties.land_cover.water.flowchange`.
let site_at = site_yaml_at(site_root);
site_scalars.flowchange = require_numeric(
    site_root,
    &["properties", "land_cover", "water", "flowchange"],
    &site_at,
)?;

// Recommended pattern for a NEW conditional parameter (BR-02/BR-03):
// Check the active physics method, switch (set in `apply_config_overrides`), or
// active-surface condition (`sfr > 0.0`) before calling `require_*`. When the
// option is inactive and the kernel does not read the field, leave it explicitly
// absent (`f64::NAN`, `LAYER_VALUE_ABSENT`, or `Option::None`) -- never call a
// legacy `read_*` fallback or invent a number.
let conditional_value = if option_is_active {
    require_numeric(
        site_root,
        &["properties", "example_parameter"],
        &site_at,
    )?
} else {
    f64::NAN
};
```

This conditional sketch is not a transcription of the existing point-source
reader. In [`apply_site_scalar_overrides`](../src/suews_bridge/src/yaml_config.rs),
`emissions_method_uses_co2_point_source` selects a required finite read for active
methods. When inactive, the reader uses
`read_numeric(site_root, point_source_path).unwrap_or(f64::NAN)`: it preserves a
supplied numeric value (including non-finite values) and uses NaN when the optional
read returns no value. The tests `missing_co2_point_source_is_accepted_when_the_method_ignores_it`
and `co2_point_source_finiteness_is_required_only_for_active_methods` in that file
record this existing behaviour; it is not permission to add legacy optional reads.

Per-surface land-cover parameters (for example `soil_store_capacity` or `soil_depth` in `apply_soil_overrides`, line 854) are likewise conditional, not unconditionally required: gate required reads on the surface being active (`sfr > 0.0`, excluding `water` where applicable) so valid configurations with an inactive surface (`sfr == 0`) are not rejected.
Existing named option predicates in `src/suews_bridge/src/yaml_config.rs` follow this pattern: `vertical_layers_are_read` (line 1056), `vegetation_layers_are_read` (line 1064), `ehc_is_on` (line 1072), `facet_layers_are_read` (line 1082), and `emissions_method_uses_co2_point_source` (line 2988), with `LAYER_VALUE_ABSENT` (line 732) as the `f64::NAN` marker for unread layer entries.
Before carrying an inactive scalar as `f64::NAN`, confirm both that the type's `from_flat` validation accepts it and that the kernel does not multiply or aggregate the inactive slot (otherwise represent the conditional field as `Option<T>` and check the kernel contract per BR-03).

Site-level scalars passed outside the member types (`lat`, `z`, `z0m_in`, ...) are a separate fixed buffer: `SiteScalars` in `src/suews_bridge/src/sim.rs`, read by `apply_site_scalar_overrides` (line 2992), encoded by `encode_site_scalars` (`sim.rs:488`) and unpacked by `unpack_site_scalars` (`c_api/driver.f95:1147`), with the length pair `SUEWS_CAPI_SITE_SCALARS_LEN` (`sim.rs:126` and `driver.f95:64`).

### 7. Python data model

This is the only place a default may live.
Add the Pydantic `Field` either with a documented default (a value, its units and why it is a sensible default, in the field description), or as required, or as required only under the options that use it (an entry in the required-field tables, `src/supy/data_model/validation/required_fields.py`).
A `None` default means "not given" and is dropped before the bridge, so the bridge will then stop if the kernel needs the value.
If the YAML schema changes, raise `CURRENT_SCHEMA_VERSION` (`src/supy/data_model/configuration/version.py:26`) and add a migration in `src/supy/util/converter/yaml_upgrade.py`; `scripts/lint/check_schema_version_bump.py` enforces this (see `.claude/rules/python/schema-versioning.md`).

### 8. Tests

- Each module's `schema_matches_expected_dimensions` and `default_state_roundtrip` tests (`stebbs_prm.rs:521` and `:527`) catch a LEN mismatch and a Rust `Default` that differs from the shadow.
- Codec/default round trips do not establish the kernel destination: the driver calls `*_unpack`, and a swapped line can survive those checks. Follow [BR-04](../.claude/rules/rust/bridge-contract.md#rules): regenerate the test-only observer, check freshness, update the [harness](../src/suews_bridge/tests/capi_field_observer.rs) for changed fields or types, and run the feature-gated live receiver tests. The maintained commands and coverage limits are in [C-API field-binding observer](../.claude/rules/rust/conventions.md#c-api-field-binding-observer):

  ```bash
  python3 scripts/suews/gen_capi_field_observer.py
  python3 scripts/suews/gen_capi_field_observer.py --check
  make -C src/suews all
  cargo test --manifest-path src/suews_bridge/Cargo.toml --features physics,capi-observer --test capi_field_observer
  ```

  The ordinary `--features physics` suite does not enable `capi-observer`.
  These tests check the named kernel receiver, not the scientific effect of its
  value. Retain a distinct-value physics wiring test where needed (model:
  [test_stebbs_parameter_wiring.py](../test/physics/test_stebbs_parameter_wiring.py)).
- Check missing, null, malformed and wrong-length input, plus both branches of any conditional requirement (BR-02/03). Cover the Python and engine routes that accept the field.
- Run `python scripts/lint/check_rust_optional_reads.py`, `cargo test --features physics` in `src/suews_bridge` (after `make -C src/suews all`) and `make test-smoke`.

Not needed for a new field in an existing type: `build.rs`, `ffi.rs`, `lib.rs`, the `impl_state_module_fns!` invocation, the driver's site-member table of contents.
A brand-new type needs all of those plus a new member index on both sides (`SUEWS_CAPI_SITE_MEMBER_*` in `driver.f95`, `SITE_MEMBER_*` in `sim.rs`, which is 0-based).

## What fails loudly and what fails silently

Loud (a test or a run-time `BadState` / `BadBuffer`):

- Fortran `SUEWS_CAPI_<TYPE>_LEN` versus Rust `<TYPE>_FLAT_LEN` (`<prefix>_default_from_fortran`, `validate_flat_len`);
- Fortran versus Rust schema version (`<prefix>_schema_info`, `from_values_payload`);
- Rust `Default` versus shadow initialisers (`default_state_roundtrip`);
- the `FIELD_RENAMES` count; the Python schema version;
- adding a new legacy optional YAML reader call in `yaml_config.rs` (`scripts/lint/check_rust_optional_reads.py`, enforced in CI).

Silent (the run goes ahead with a wrong value):

- `*_unpack` order differing from `*_pack` and Rust: the right number lands in the wrong kernel variable;
- `<prefix>_field_names()` shorter than `to_flat()`: `to_map` zips the two and drops the tail (only `<prefix>_schema_info` compares the lengths);
- Fortran accepting a buffer longer than LEN (the facades check `n_flat < LEN` only);
- a STEBBS or archetype YAML key that matches no Rust field (`set_mapped_value` drops it);
- an absent key, or a Pydantic `None`, leaving the shadow default (usually zero), in the readers not yet converted to the pass-through rule;
- a hard-coded slice bound in a parent type that starts in the wrong place while the total length is right;
- the two `SUEWS_CAPI_SITE_SCALARS_LEN` constants and the index of each site scalar, which are not compared at run time.

## Checklist

- [ ] Kernel `TYPE` component added, with units, established range and representation initialisation documented.
- [ ] Shadow component added; its representation initialiser is consistent with the kernel's and cannot replace missing input.
- [ ] Facade LEN and schema version raised.
- [ ] One line in `*_pack` and one in `*_unpack`, at the same position; INTEGER via `nint`, LOGICAL via `>= 0.5`.
- [ ] Rust `*_FLAT_LEN` and `*_SCHEMA_VERSION` match the facade.
- [ ] Struct field, `Default` (equal to the shadow), `from_flat`, `to_flat` and `*_field_names()` all at the same index.
- [ ] Range check in `from_flat` if the value has a valid set.
- [ ] Nested type: every parent's LEN, slice bounds and inlined pack/unpack updated.
- [ ] `FIELD_RENAMES` (Rust and Python) and its count test updated if the names differ.
- [ ] YAML reader: strict `require_*` helper (`require_numeric`, `require_i32`, `require_string`, `require_sized_numeric_sequence`, or `require_sequence`) added for unconditionally required fields and active option- or surface-gated branches (with explicit absence such as `f64::NAN` / `LAYER_VALUE_ABSENT` / `Option::None` when inactive); no new legacy optional `read_*` calls (`python scripts/lint/check_rust_optional_reads.py` passes, lowering the baseline via `--write-baseline` if migrating an existing site); for map-based STEBBS/archetype blocks, presence validated explicitly in addition to name matching.
- [ ] Pydantic field with a documented default, or required (conditionally on the options that use it); no application default in Rust or the shadow; schema version and migration if the schema changed.
- [ ] Missing/null/malformed/wrong-length inputs and option branches checked; audit evidence records the affected BR rules and unresolved gaps.
- [ ] Observer regenerated and `--check` passes; harness updated and `physics,capi-observer` live receiver tests pass (step 8).
- [ ] Distinct-value physics wiring evidence where needed; `cargo test --features physics` and `make test-smoke` pass.
